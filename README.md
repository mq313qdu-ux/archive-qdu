# أرشيف الأثر النافع — 2025 — 2026

متحف وأرشيف بصري رقمي فخم وشخصي، خُصص لحفظ وتخليد رسائل الطلاب ومشاعرهم الصادقة خلال مسيرة سنوات الدراسة في 2025 — 2026، لتبقى ذكرى دافئة وأثرًا طيبًا مستمرًا.

---

## 1. بنية الملفات (File Structure)

تم تنظيم المشروع ليعمل مباشرة كـ Static Web Application متوافق 100% مع GitHub Pages وبدون أي تعقيد أو Build Step إلزامي:

```text
archive-rehlat-al-athar/
│
├── index.html            # الصفحة الرئيسية للأرشيف
├── style.css             # ملف الأنماط والتصميم السينمائي (Dark Cinematic)
├── script.js             # محرك الأرشيف، التفاعل، الـ Lightbox، والمفضلة
├── README.md             # دليل الاستخدام والتطوير الكامل
├── 404.html              # صفحة الخطأ 404 المتوافقة مع الهوية البصرية
│
├── صورة (1).jpg           # صور الرسائل موضوعة في المجلد الرئيسي مباشرة
├── صورة (2).jpg
├── ...
├── صورة (94).jpg
│
└── assets/
    ├── logo.png          # الشعار الرسمي للأرشيف
    ├── favicon.png       # أيقونة المتصفح
    └── og-image.jpg      # صورة المعاينة لشبكات التواصل (Open Graph)
```

> **ملاحظة هامة:** صور الرسائل تكون بجانب `index.html` مباشرة دون وضعها داخل مجلد فرعي، مع الحفاظ على صيغة التسمية العربية الأصلية `صورة (X).jpg`.

## 3. كيفية إضافة رسالة جديدة مستقبلاً

الموقع مبني بديناميكية كاملة لدعم التوسع المستقبلي بسهولة:

1. أضف الصورة الجديدة إلى المجلد الرئيسي بنفس نمط التسمية، مثلاً:
   `صورة (95).jpg`
2. افتح ملف `script.js` وقم بتعديل قيمة `totalImages` في `ARCHIVE_CONFIG`:
   ```javascript
   totalImages: 95,
   ```
3. سيقوم الموقع تلقائيًا بتحديث:
   - المعرض (Gallery) وإضافة البطاقة في مكانها الصحيح.
   - عداد الرسائل في الفوتر وأدوات الـ Lightbox.
   - ميزة "فاجئني برسالة".
   - انتقال Easter Egg الخاص بآخر رسالة للرسالة الجديدة تلقائيًا.

## 4. تغيير اللوجو وصور Hero

- **تغيير اللوجو:** استبدل ملف `assets/logo.png` بملف الشعار الجديد الخاص بك (ويفضل أن يكون مربعًا بخلفية شفافة أو سوداء فخمة)، وسيتم تحديثه في الهيدر، الفوتر، شاشة التحميل، والـ Favicon.
- **تغيير صور الـ Hero:** يمكنك اختيار أي رسائل مفضلة لعرضها في مقدمة الموقع من خلال مصفوفة `heroImages` داخل `ARCHIVE_CONFIG`.

## 5. تشغيل الموقع محليًا (Local Development)

يمكنك فتح ملف `index.html` مباشرة في أي متصفح حديث، أو تشغيل خادم محلي خفيف:

```bash
# باستخدام Python
python -m http.server 3000

# أو باستخدام Node / npx
npx serve .
```

ثم التوجه إلى: `http://localhost:3000`

## 6. خطوات النشر على GitHub Pages

1. أنشئ مستودعًا جديدًا (Repository) على حسابك في GitHub.
2. ارفع جميع ملفات المشروع (`index.html`, `style.css`, `script.js`, `404.html`, مجلد `assets`, وصور الرسائل).
3. ادخل إلى إعدادات المستودع (**Settings**).
4. من القائمة الجانبية اختر **Pages**.
5. تحت قسم **Branch**، اختر الفرع الرئيسي (`main` أو `master`) والمجلد `/ (root)`.
6. اضغط **Save** وانتظر بضع ثوانٍ حتى يتم بناء ونشر الرابط الرسمي للموقع.

## 7. حل المشكلات الشائعة (Troubleshooting)

- **صورة لا تظهر في المعرض؟**
  تأكد من مطابقة الاسم بدقة للحروف العربية والمسافات والأقواس: `صورة (X).jpg` حيث X يمثل رقم الصورة بدون أصفار بادئة (مثل `صورة (7).jpg` وليس `صورة (07).jpg`).
- **مشاكل المسارات مع GitHub Pages:**
  المشروع يستخدم `encodeURI()` تلقائيًا للتعامل مع الرموز واللغة العربية والأقواس في مسارات الصور مما يضمن عملها بشكل سليم عبر كافة المتصفحات والأنظمة السحابية.
- **المفضلات:**
  المفضلات تعمل بنظام الذاكرة الحية للجلسة (Session-only In-Memory) دون الاعتماد على LocalStorage، ويتم إعادة ضبطها عند تحديث الصفحة كما هو محدد بالمواصفة القياسية للأرشيف.
